# Demo dataset (GPX)

Used by the guest/demo mode (`DemoDataSeeder`, see ADR 0011). `runs.json` (owned by backend-dotnet) references these files by name.

## Provenance

All tracks are **synthetic**. They were generated by [`tools/generate_gpx.py`](tools/generate_gpx.py) (Python 3 stdlib only, deterministic seeds; re-run `python3 seed/demo/tools/generate_gpx.py` to regenerate byte-identical files). The script is kept in the repo so the files can be regenerated or tuned reproducibly.

- Hand-drawn loops in local metres around Gliwice, Labedy and Ustron (Silesian Beskids), smoothed, scaled to the exact target distance, with ~2 m of slow synthetic GPS wander. They only roughly resemble real streets or paths.
- Elevation is invented (smooth control profile plus a small wiggle), not taken from any elevation model.
- Timestamps are synthetic (fixed 2025 dates, speed varies with grade, fatigue and start congestion; finish time is exact). They are not tied to any person or real event. `runs.json` shifts run dates; the GPX timestamps stay fixed.
- **No third-party base data** (no OpenStreetMap, no real recordings, no DEM), hence no external licence obligations. No personal data.
- Valid GPX 1.1 (`http://www.topografix.com/GPX/1/1`), no DOCTYPE/DTD/entities, one `trk` with one `trkseg`, all files < 130 KB.

## Files

Distance is haversine (R = 6371008.8 m). Gain/loss use a 3 m hysteresis threshold and are the whole-metre values the server pipeline (`TrackProcessor`, ADR 0021) computes from the committed files (elevations rounded to 0.1 m); `runs.json` carries the same figures. They differ by a few metres from what `generate_gpx.py` computed from its unrounded data. Distances are within 1 m of the pipeline values. Race names are not in the files; the "belongs to" column is a suggestion for `runs.json`.

## `runs.json`

The week-relative dataset every guest gets a private copy of (ADR 0011). `week` 0 is the current ISO week in `timeZoneId` (`Europe/Warsaw`), negative weeks are the past (-26..-1), positive weeks the future (1..5); `day` is `Mon`..`Sun`. Entries dated after "today" are turned into plans when a guest is created (results, rating, heart rate and recorded track are dropped). `type` is a run type code from the catalog. `gpx.file` is relative to this directory; recorded tracks belong to completed races, planned courses to planned races.

- ~120 entries: weekly easy / quality / long runs for a recreational 10K-to-half-marathon runner (24-52 km per week), a few rest and cross-training days.
- Races: 10K road (week -20), cross-country 6K (-13), half marathon (-7) and a trail race (-3) are completed with result, rating and recorded track; a 10K (week 3) and a half marathon (week 5) are planned with a course.
- Load story: a spike week (-11, about 1.6x the preceding four-week mean) followed by a down week, and a taper week (-8) before the half marathon. Under the M5 metrics (ADR 0024: session load = RPE x minutes, uncoupled 7/28 ACWR) the spike week ends at ACWR 1.48 ("high"), the taper week at 0.55 ("low"), and the week of the trail race (-3) peaks higher still (1.59).
- Pace story (M5): the `easy` runs get faster over the 26 weeks, from about 5:55 /km (week -26) to about 5:40 /km (week 0, planned weeks keep ~5:40), with a few seconds of deterministic noise, so the Insights easy-pace trend has a visible downward slope (about -0.6 s/km per week). Only the `durationSeconds` of `easy` entries were tuned (distances, heart rates and RPE are unchanged), which also moved the weekly loads by a few AU.
- Guarantees (per "today") are enforced by `DemoDatasetTests` and, for the metrics (spike = ACWR "high", taper = "low", easy-pace points, races), `DemoInsightsTests` in `tests/RunnersDiary.Domain.Tests`; the golden report snapshot `tests/RunnersDiary.Domain.Tests/Insights/golden/demo-report-v1.json` must be regenerated (`UPDATE_GOLDEN=1`) whenever this file changes. All content is synthetic; the file is hand-tunable, there is no generator.
