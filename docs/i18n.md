# Runners Diary – Localisation guide (en, pl)

Living document, owned by the `architect` agent. Decisions: [ADR 0042](adr/0042-ui-localisation-and-language-preference.md) (UI) and [ADR 0043](adr/0043-ai-outputs-in-polish.md) (AI). Status: **proposed with the [M10 plan](plans/M10-polish-localisation.md); the glossary below is a draft for the user's review.**

## 1. Rules for every PR that adds or changes user-facing text

1. Add the key to `web/src/i18n/en/<ns>.json` **and** `web/src/i18n/pl/<ns>.json` in the same PR. The parity test fails otherwise.
2. Plurals: English `_one`/`_other` means Polish `_one`/`_few`/`_many`/`_other`, called with `count`. Never build a plural from two keys or a ternary.
3. Interpolated nouns (run type, race name, band, date) are inserted in the **nominative**. Shape the Polish sentence so that works: after a colon, as the subject, or in „quotes”. Example: `Usunąć trening „{{type}}” z dnia {{date}}?`, not `Usunąć {{type}}…`.
4. No hand-formatted numbers, dates or units in strings. Use the formatters in `lib/format` and `lib/dates` with `i18n.language`.
5. Seeded demo texts (`seed/demo/*.json`): add the Polish text to `seed/demo/i18n/pl.json`. The seeder test fails otherwise.
6. AI-visible wording (prompts, templates, demo fixtures) follows ADR 0043. A prompt change is a new prompt version.
7. Drafts: the implementing agent (usually `frontend-react`) writes the Polish text using the glossary. **The user reviews the Polish diff** before merge. Reviewers flag Polish strings without review in the PR checklist.

## 2. Tone and style (pl)

- **Informal "ty"**, friendly and short, like the English UI. No "Pan/Pani".
- **Gender-neutral.** No gendered past-tense or first-person forms ("zapisałeś/zapisałaś", "Zapisałem się"). Use instead:
  - imperatives ("Dodaj trening");
  - present tense ("Bierzesz udział");
  - noun phrases ("Zapisy potwierdzone");
  - impersonal forms ("Dodano trening").
  Avoid "(a)" slash forms unless nothing else reads naturally.
- **Sentence case** for headings and buttons. Month and weekday names are lower case in running text and capitalised only at the start of a heading. The month header uses `capitalizeFirst`.
- Polish quotation marks „…”, an en dash with spaces for ranges in text (`10–12 km` via the formatter), the ellipsis character `…`.
- Numbers: decimal comma; thousands separated by a non-breaking space from 10 000 (Intl `pl`). Pace `5:30 /km`, durations `1:45:30`. Units are not translated (`km`, `m`, `AU`).
- Keep strings short. Calendar cells, bubbles and header buttons must fit 360 px. If the Polish text is much longer than the English, shorten the Polish instead of shrinking the layout.

## 4. Checks

- `npm --prefix web test -- --run`: the parity test covers keys, variables, plural forms, empty values and "same as English" with an allowlist. `npm --prefix web run test:tz` runs the `pl` formatting tests.
- Playwright projects `desktop-pl` and `phone-pl` (M10).
- `dotnet test`: seed translation completeness, Polish validator rules, templates and demo fixtures.
